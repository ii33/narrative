# 数据模型

工程存储使用 schema 11。节点保存当前对象，属性保存事件处的建立、变更和失效操作；读取不重放修订日志。

## 身份、证据与阅读位置

节点包括人物、群体、物品、地点、主要故事、大事件、场景、事件、动作和其他。每个节点有稳定的类型编号、名称、别名、语境、原文证据和首次披露位置；节点改名不改变身份。节点没有修订旧版本。

阅读位置由原文来源顺序与 Unicode 字符偏移组成：`{source_id, start}`，可附 `event_id`。偏移不是 UTF-16 单元，结束位置不包含在范围内。来源顺序保存在 `source_order`，不能用编号、录入时间或文件名代替。补录早先事实不会变成最新状态。

动作使用 `action` 类型与 `A` 编号，低于事件；必须直属恰好一个同语境活动事件，不能直接挂在场景下或继续包含子项。阅读层级为主要故事（storyline/T）→ 大事件（big_event/B）→ 场景（scene/S）→ 事件（event/E）→ 动作（action/A），跨层级顺序按原文披露位置判断，不能比较 E/A 编号。

原文与附件保持独立存放。精确证据使用来源、起止位置和逐字引文。事件可以有多处披露证据；同名、同段或位置相近不能单独证明是同一次事件。

## 当前节点与包含关系

`objects` 每个 ID 只有一行当前对象。更新直接修改该行，不保存对象旧副本。主要故事以 `events` 包含大事件，大事件包含场景，场景包含事件或嵌套场景，事件包含动作；禁止包含循环，每个活动事件必须经包含路径属于同语境的活动场景，单事件场景也成立。

主要故事只在完整大篇章结束后总结创建；未结束时积累大事件、场景和事件，大事件可暂不归主要故事，不创建临时主要故事。提取草稿用逐字且唯一的 `closing_quote` 定位结束证据，程序设置总结披露点为引文起点、`completion: {source_id,start}` 为引文末端的半开右界。容器可用 `children` 引用已有直属子项，因此总结主要故事只需关联已有大事件，不需重列整篇节点与旧引文。

主要故事和大事件都只有一个清晰概括的 `name`，不存暂称／正式名双轨，也不添加暂称后缀。大事件同语境依原文披露位置形成 `[start,next.start)` 连续阅读区间；末个大事件若已归入完成的主要故事，以其 `completion` 封口，否则 `end=null`。主要故事范围起点来自成员大事件，终点为显式闭合右界；这些都是阅读区间，不是故事发生时间。

`storyline_progress`（主要故事进展）记在直属大事件上，`big_event_progress`（大事件进展）记在直属场景上，容器按当前阅读位置汇总相应子级，不把旧场景进展解释为主要故事进展。

事件物理合并重写所有有类型的引用，将证据和子项并入保留对象，删除被合并对象；不保留合并重定向链。字符串正文不因恰好等于某节点 ID 而被改写。

## 属性事件变更

正式记录为当前 `property_definition` 与 `property_change`。变更必带事件、操作和事件内序号，不再有 `valid_from`、`valid_to`、有效期或 `expirations`。建立和修改使用 `set`，增加／移除用 `add`／`remove`，整组失效用 `clear`，明确未知用 `unknown`。错录直接更正或删除，不伪造状态变化。

程序按正式来源与事件位置、同事件 `sequence` 推导指定位置的状态。原文提取序号由定位引文生成；人工新增明确追加。单个人际对象有独立状态序列，不会因记录另一位朋友而替换前者；`many` 则表示一个数组集合，不能混用这两种含义。同事件同序号冲突必须诊断，不按记录ID或录入顺序猜测。

对称关系由定义的 `symmetric` 严格布尔字段表达；不按名称词表猜测，不补写无证据的反向变更。作用域、持有人和语境分别推导。物品须有明确的world持有状态（节点、无或未知），缺失或清除不等于未知。完整合同见[属性状态合同](PROPERTY_STATE_CONTRACT.md)。

## 修订与回退

`revision` 只用于并发检查。轻量动作审计记录动作、原因及 ID／数量摘要，不保存整份节点或数据库快照；没有可回放的修订对象表。原始模型输出和任务诊断独立保存，不能当作当前事实读取。

按阅读时间点回退先预览，再在同一事务中删除该点之后的节点与变更、清理引用，再按剩余变更推导状态。边界点本身保留。回退不恢复节点的旧名称或旧编辑副本，因为这些版本不存储。若删除将破坏场景、引用、持有者等静态约束，整个事务拒绝，不能伪造事实补齐。

## 校验与旧工程

UI、CLI 与 agent 均通过 `Operations` 写入。结构、引用、逐字证据、包含关系、值类型、事件顺序、状态冲突与持有者等静态检查在提交事务前执行；独立静态检查页可手动检查和跳转问题。

仅支持当前 schema 11；旧版工程直接拒绝打开，不提供兼容读写、转换或迁移入口，原文件不改动。

## 工程提取粒度

工程设置保存 `extraction_granularity`：`standard`（阅读梳理）或 `fine`（默认精细）。事件是在同一语境里有独立叙事意义的完整发生或过程，同一叙事目标的准备、实施、即时结果与收尾优先合成一个事件；新信息、决定或结果本身不自动切界，须引发后续独立展开的新目标、矛盾或情境进展才另列。连续动作链、姿态与操作细节归入所属事件，不按句子、动词或每次属性变化拆成E。fine细查有独立意义的转折、信息节点和人物地点证据，不将动作改标为事件。

例如起身、取资料、递交若只是一次交接过程，概括成一个交接事件；阅读后获知新信息、当场决定如何处理，若仍属于本次交接的即时处理则不另切事件；后续独立展开另一个目标过程时才另列。具体动作若引出原文明示的后续独立展开，仍可作为事件；仅有直接结果不自动构成独立边界。边界由模型语义判断，不使用题材或动词黑名单，也不新增语义静态拒绝。

事件的 `participants` 引用原文明示出场或实际起作用的人物；有原文依据的地点通过事件属性记录：`node=事件`、`property=地点`、`value=地点节点`、`value_type=node`、`scope=world`，并用 `at_event` 锚到该事件、以逐字引文支持。地点不放进 `participants`。精细档额外细查非关键及无名人物、具体地点，不臆造身份或把无法区分的泛称拆成多个节点；场景等上层从成员派生，无需重复写地点属性。

两档默认都不提取动作。在事件节点编辑器点击“动作提取”时，向当前统一助手会话提交一个带父事件 ID 的任务，读取原文及已有动作后按需新增/复用动作；不另启提取进程，也不重提整章。常规事件粒度与动作展开独立。

模型配置复用项目现有 Provider 设置，粒度随工程保存。新任务读取当前设置，改变设置不自动重提既有数据。

## 稳定编号与直接批写

原文使用 `SRC1`、`SRC2`，属性变更使用 `PC1`、`PC2`，切片使用 `SRC1-SL1` 等真实存储编号，不维护另一套短名映射。编号由程序分配；属性变更计数器与事实同事务更新，删除后不复用。节点仍使用P/E/A等类型编号，属性定义继续用语义名称。项目/聊天/SDK调用等内部身份不进入普通事实工具参数；内容hash仅用于程序校验。

取值去重使用主体、属性、类型化值、作用域、认知持有人、披露位置、原文证据和适用事件等完整字段，不以截断hash充当去重规则。不同作用域/持有人或不同披露位置的记录分别保留；相同事实的分类等注释更正不新造取值。

自动提取和通用修改不再使用暂存候选表或propose/accept链。一次只读事务捕获同版对象、属性、原文和修订；宿主完成一次准备与静态校验，预先计算并序列化变化行。写事务仅核对修订、提交差异行、推进编号与写操作摘要，失败全部回滚。仍保留一轮完整静态校验，并非全部计算只随增量增长。

单原文工具可省略source_id，多个原文须明确指定；批量引文定位一次读取原文并复用重复quote结果，输出原文坐标、准确性/截断诊断。规律章节由程序同事务扫描、校验并创建，不需要模型往返source_hash/plan_id。
