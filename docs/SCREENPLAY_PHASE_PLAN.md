# 剧本功能开发计划与数据结构约定

日期：2026-11-03  
状态：剧本闭环已实现；最新四栏与独立副本导入的合同及验收见10.1。第10节保留基础阶段功能结果和当时的预算异常，不与本次结果混算。

实现约束：不考虑任何版本兼容性。只实现当前目标数据结构和接口，不设计旧格式读取、数据迁移、旧客户端支持、兼容字段、双轨存储或兼容测试。现有业务数据均为可丢弃的开发测试数据，结构调整允许直接清库、删除测试产物并重建，不要求备份、保留旧数据或历史结果。此约定针对数据，不授权丢弃工作区代码改动。

开发重置与正常业务行为分开：并发检查、原子提交、局部编辑范围及取消后保留已完成提交仍是产品正确性合同。本轮验收证据仍按实际请求记录，隔离库用于结果归因和可复现，不承担旧数据保护要求。

## 1 阶段目标与边界

新增“剧本”功能，形成如下完整闭环：

1. 查看改编时间列表的主要故事、大事件、场景、事件、动作五级结构。
2. 先从改编时间线多选导入节点及相关状态到本剧本的独立副本，再选取连续时间点创建时间段，绑定为本剧本段落。
3. 针对段落拆场，形成可反复编辑、讨论和修改的场表。
4. 采用当前场表后，逐场或批量生成正文；每场继续支持手工编辑及对话修改。
5. 在独立结构页中，用集和幕组织同一批段落。

段落是剧本主表的基本单元，场次是写作与正文提交的基本单元。场表与正文共用场次对象和稳定 ID。改编时间段是剧本段落唯一的直接来源绑定，场次不要求绑定单个原文或事件。

本阶段不包含分镜编辑、媒体生成、配音生产、成片时间轴、复杂协作权限或专业排版编辑器。保留未来镜头引用场次及正文块的稳定 ID。本阶段导出可阅读的 UTF-8 剧本文本及结构化 JSON；PDF、Fountain 等专用导出后续扩展。

只编辑计划不触发真实模型请求。正式实施遵循 AGENTS.md；其中旧数据保留要求按本次用户明确指令取消，其余开发和验收规则继续适用。旧 docs/PLAN.md 中涉及人工接受的历史规划不适用于本功能。

## 2 现状与设计继承

当前工作区已有改编节点排序、屏蔽、改编属性和读取投影等开发代码；这些改动尚不能仅凭文件存在就视为完成验收。改编时间段、剧本、场表及幕／集组织均属本阶段新增。

本文继承 [原设计](SCREENPLAY_DATA_DESIGN.md) 的范围解析、内容块类型和原作隔离原则，明确替换以下早期约定：

| 早期设计 | 本阶段约定 |
| --- | --- |
| 一集一份 Screenplay | Screenplay 表示一部作品的一套剧本方案，可含多集；集为独立组织实体 |
| 所有大结构均为单元范围分组 | 集／幕以段落为成员，按严格树形组织；楔子／尾声作为段落角色，不引入第二套排序 |
| 先生成段内完整正文 | 先生成场表，再逐场提交正文 |
| 一个段级正文依据 | 场表依据保存在段级，正文依据分别保存在场次级 |
| 所有编辑仅靠整份剧本 revision | 内容使用对象修订号，结构用剧本结构修订号，避免其他场次编辑阻塞当前场 |

只保存当前业务对象；revision 用于并发检查，不新增节点旧版本、撤回或重放系统。任务记录保留输入、输出和审计材料，与业务对象版本分开。

## 3 页面与用户流程

### 3.1 剧本工作页

- 工作页固定四个并列栏：改编时间表、段落表、场表、正文。每栏可独立折叠为可展开的窄标题条，折叠不清除选择或编辑状态；栏宽可拖动调整，窄窗可横向滚动。
- 改编时间表显示本剧本显式导入的五级节点副本，支持“从改编时间线导入”的多选入口、范围选择、实际范围、屏蔽数和诊断；不默认展示或跟随整份源改编。
- 段落表列出名称、范围摘要、所属集／幕、场数、目标／估计时长、完成进度和来源变化。
- 场表和正文同时呈现，共享同一批场次；点击场表行切换对应正文，不再用互斥Tab隐藏另一栏。
- 统一对话：在当前聊天中附带显式修改目标，不增加独立生成会话或审核工作台。

“采用场表”是工作标记，随时可修改，不冻结编辑、不形成待人工审批队列。明确要求一并拆场和写作时，agent 可以在同一任务内连续完成，不要求用户再点击接受。

### 3.2 结构页

单列“结构”页，编辑集、幕、段落归属和结构说明。这里引用主表同一批段落，不复制概要或排序。结构页和工作页的调序调用同一 Operations 操作。

第一版支持两种结构模式：

- 单片：Screenplay → 可选幕 → 段落。
- 剧集：Screenplay → 集 → 可选幕 → 段落。

同一层允许幕和未归幕段落按序混排。剧集中的段落必须归某集；初建时自动创建第1集。一个段落不跨幕、不跨集，需要时显式拆段。改变单片／剧集模式必须同时提交完整重组，不隐式搬动已有内容。

## 4 数据对象与身份

公共字段采用稳定 string ID、UTC 时间戳和整数 revision。ID 不编码次序；position 只在所属列表内表达顺序。所有可写对象必须通过类型化 schema 校验。

### 4.1 对象清单

| 对象 | 核心字段 | 归属与约束 |
| --- | --- | --- |
| Screenplay | id, timeline_id, title, format, language, creative_brief, revision, structure_revision | format 为 single 或 series；一套剧本方案；timeline_id指向其独占副本 |
| ScriptTimeline | id, screenplay_id, revision, nodes, properties, source_revision, 导入基线 | 每份剧本创建空副本；节点和状态按来源改编当前sort_id复制，不编码原文阅读顺序 |
| ScriptEpisode | id, screenplay_id, number, title, brief, target_duration_seconds, position, revision | 仅 series 可用；number 为显示编号，position 为真实顺序 |
| ScriptAct | id, screenplay_id, episode_id?, title, brief, target_duration_seconds, revision | single 时 episode_id 为空；series 时归一集 |
| StructureEntry | id, screenplay_id, parent_kind, parent_id, child_kind, child_id, position | 唯一权威组织和排序关系 |
| AdaptationSpan | id, timeline_id, name, start_node_id, end_node_id, revision | 双端包含，稳定锚点，动态解析成员 |
| ScriptSegment | id, screenplay_id, span_id, title, role, brief, target_duration_seconds, enabled, revision, outline_revision, outline_basis_id?, adopted_outline_revision? | 恰好绑定一个时间段；role 为 normal/prologue/epilogue |
| ScriptUnit | id, segment_id, kind, position, enabled, scene_number?, plan, plan_revision, body_revision, revision, body_basis_id? | kind 为 scene/screen_segment；场表行与正文容器同一对象 |
| ScriptBlock | id, unit_id, position, type, payload | 正文块；随所属场的 body_revision 做并发控制 |
| WritingBasis | id, target_kind, target_id, stage, span_fingerprint, context_fingerprint, plan_fingerprint?, manifest_ref, task_id?, created_at | 段落场表或单场正文的当前依据 |
| EntityUsage | id, unit_id, block_id?, entity_id, role | 改编实体引用；role 区分出场、发声、提及、使用等 |

StructureEntry 允许 screenplay→episode（series）、screenplay→act/segment（single）、episode→act/segment、act→segment。一个集、幕或段落恰好有一个入口；不允许环、重复归属或跨剧本引用。全局段落顺序由树的深度优先遍历得到，不再保存在 ScriptSegment.position 中。场次的 position 则仍在段内唯一。

删除非空集／幕必须选择明确的搬移目标，不能默认删除段落。拖动段落到另一集时同时更新组织入口；不影响来源时间线。

### 4.2 时间段约定

当前改编→剧本关系采用用户确认的独立副本：创建剧本时建立空 ScriptTimeline；多选导入仅带入所选节点、必要祖先／参与实体／状态引用闭包及真实区间边界。源改编后续修改或删除不影响副本；剧本内节点、排序、屏蔽、属性调整不回写源或其他剧本。显式再次导入用来源基线三方合并，保留本地编辑与顺序，冲突留诊断。

节点ID可沿用源身份，但始终由独立timeline_id限定数据域，不能按相同ID误判跨剧本引用。所有段落、场表、正文、实体校验、依据及导出按所属剧本副本解析，不回退读取源改编。时间段不可跨剧本共享或绑定；不同剧本可分别导入同一来源范围并创建各自时间段。

AdaptationSpan 表示当前剧本独立时间线上的动态连续范围，不能用既有 point_id 或资产时点代替。preview/create必须显式给screenplay_id，创建或更新用expected_timeline_revision；导入另外校验源expected_adaptation_revision。

- 规范范围成员为改编事件／动作，按 sort_id 排序；选择高层容器时展开有效后代解析端点。
- 选区是规范时间轴的连续范围，过滤和折叠不改变成员；父子选择去重，不自动提取动作。
- 边界保存事件／动作 ID，不保存数组下标、sort_id 数值或原文位置。
- 屏蔽边界仍可定位，屏蔽内容不送入目标写作输入；全部屏蔽得到 empty。
- 内部插入、移入、移出或调序按当前边界重新解析；旧正文不自动改变。
- 删除锚点或端点顺序倒置得到 invalid，不猜测替代边界；现有正文保留。
- 同一段落只绑定一个范围，允许单节点范围；范围重叠给出提示，不自动去重或禁止。
- 范围外前后文可以只读参考，不扩展改编目标。

目前按稳定锚点定义动态范围是本计划的默认实现决定。某次写作实际使用的成员清单保存在任务输入 manifest 中，不反过来将当前范围冻结成成员集合。

### 4.3 场表 plan

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| title | string | 场表短标题 |
| interior_exterior | enum | INT/EXT/INT_EXT/UNSPECIFIED；独立画面段不需要 |
| location_id | nullable string | 改编地点实体引用 |
| location_text | string | 可先写文字；有引用也可保留局部剧本表达 |
| time_label | string | 夜、连续、次日晨等；允许草稿为空 |
| story_time | nullable object | 可选故事日／相对关系，不是成片秒数 |
| cast_ids | array[string] | 本场计划出场的改编人物／群体，允许草稿未绑定 |
| summary | string | 本场剧情概要，拆场提交至少需要非空概要 |
| goal / conflict / outcome | string | 可空；明确戏剧目标、冲突、结果 |
| estimated_duration_seconds | nullable number | 正数，估计而非实际片长 |
| narrative_mode | enum | normal/flashback/dream/imagined |
| continuity_requirements | array[object] | 人物状态、服装、物品持有等明确要求 |
| production_notes | string | 特效、环境声等制作备注 |
| presentation | nullable enum | 独立画面段使用 title_card/black_screen/credits/other |

场表 cast_ids 是创作计划，正文实体使用清单是实际表达，两者并存用于比较，不互相静默覆盖。未绑定人物可以通过对白 speaker_label 表达并生成提示，不自动创建原作人物。原作静态约束不机械套用到虚构剧本，但所有 ID 引用和类型必须正确。

### 4.4 正文块

沿用五类：action、dialogue、screen_text、sound、transition。dialogue 包含 speaker_id（可空）、speaker_label、text、delivery 和 parenthetical；delivery 区分现场、画外、旁白和内心声。

块与镜头不一一对应。片名独立出现时用 screen_segment，叠在行动画面上时用场内 screen_text。楔子为段落 role，可以位于幕外，不将其误建为字幕。

没有正文不等于生成失败，单元可长期停留在场表阶段。清空正文是明确编辑动作，不伪装成自动恢复。

## 5 状态与修订规则

### 5.1 场表采用状态

场表的行增删、顺序调整或任一 plan 修改使段落 outline_revision 递增；场号和纯导航标题不影响内容指纹，但仍属于编辑修订。采用当前场表时记录 adopted_outline_revision，撤销采用时设为空。

读取时：无采用记录为 planning，相等为 adopted，不相等为 changed。生成某场的必要条件是范围有效且该场具备可用概要，不是 adopted。采用状态只表达用户／agent 的工作意图。

### 5.2 正文状态

正文存在性与输入一致性分别返回，避免一个枚举混合不同概念：

- body_presence：empty 或 present。
- basis_state：unbased/current/changed/invalid/empty_source。
- generation_activity：由当前任务派生 running/cancelled/failed/completed，不作为场次永久质量标签。

每场正文依据独立保存，某场生成成功不将整个段落标为已同步。手工改对白不自动刷新来源依据。明确核对后可记录新的 WritingBasis，并保留理由。

### 5.3 影响判断

| 修改 | 处理 |
| --- | --- |
| 场号、导航标题 | 更新显示，不要求重写正文 |
| 本场地点、人物、概要、目标、结果 | 本场正文标记需要复查 |
| 场表增删或调序 | 重算邻接上下文依赖，相关场提示复查 |
| 上一场正文或结尾变化 | 仅对实际依赖该内容的后续场标记变化 |
| 绑定范围有效输入变化 | 场表依据及相关各场正文标记变化 |
| 无关范围外节点变化 | 不标记过期 |
| 改剧本／集／幕创作要求 | 对实际使用这些要求的场表和正文重算依赖 |
| 手工修改正文 | 保留当前正文，增加 body_revision；影响实际依赖它的相邻场 |

指纹使用规范化实际输入，排除更新时间、纯存储排序数值和无关全局 revision。字段是否属于输入由版本化输入投影定义，不依赖临时关键词判断。

## 6 编辑、讨论与生成合同

### 6.1 修改范围

当前对话附带 target：screenplay/episode/act/segment/scene_table/unit/blocks，并给出明确 ID 列表。允许用户在同一聊天切换目标；每个操作参数仍须显式指定对象，不能读取一个会随 UI 变化的全局目标。

修改意见和解释留在现有聊天记录；原始工具调用和诊断留在任务记录，不另建重复消息数据库或意见审批状态机。模型操作返回已改对象和影响摘要。非目标场的正文不得被顺带覆盖；跨场修改必须属于本次用户指令范围。

### 6.2 拆场提交

submit_scene_table 原子提交段内场表及场表 WritingBasis：首次创建场次；已有场表时优先按稳定 ID 更新。不能靠行号或标题匹配身份。

重新拆场不得自动清空已有正文。删除、拆分、合并已有场必须传递显式操作和正文处理策略；实现首版可先提供手工迁移正文块与删除，复杂操作不可用时清晰报不支持，不偷偷重建整表。

### 6.3 单场与批量正文

- 单场输入含绑定时间段、本场 plan、段落要求及必要前后场上下文。
- 默认批量仅选 enabled 且正文为空的 scene；已有正文只有被明确指定重写时才进入目标。screen_segment 可单独编辑或明确纳入任务，不默认为普通场景生成。
- 批量是同一用户任务中的多个逐场原子提交，不是宿主固定分轮提取流程。执行顺序默认按剧本顺序，后续场读取已提交的前场正文。
- 每场提交验证 expected_plan_revision、expected_body_revision、绑定及实际上下文指纹。别场无关编辑不阻塞本场；当前场或依赖变化则拒绝覆盖。
- 成功场即时保留；失败、取消不回滚已提交场。整项任务终止原因与逐场提交结果分别展示。
- 不自动开新真实请求重试，不设固定轮次或任务总时限。错误反馈、用户停止和常驻会话遵循现有合同。

批量目标清单保存在任务输入中；任务执行中调序、删除或新增场不会静默改变该清单，重新读取时报告差异，需按明确的新指令调整。

## 7 接口与存储约定

所有以下名称是拟新增 Operations 能力，需同步工具表、CLI、MCP 和 UI。

| 能力组 | 拟新增操作 |
| --- | --- |
| 范围 | preview_adaptation_span, create_adaptation_span, update_adaptation_span, read_adaptation_span |
| 容器与结构 | create_screenplay, read_screenplay, apply_screenplay_structure |
| 段落 | create_script_segment, update_script_segment, read_script_segment |
| 场表 | submit_scene_table, apply_scene_table_changes, adopt_scene_table |
| 正文 | read_script_unit_context, submit_script_unit, apply_script_block_changes |
| 依据与检查 | mark_writing_basis_current, check_screenplay, export_screenplay |

通用变更操作为类型化动作数组，不开放任意 SQL／JSON 路径补丁。每批写入提供相应 expected revision 和 reason；子对象编辑更新自身与相关聚合计数，但不要求所有无关对象版本一致。

在工程 SQLite 中建立独立 screenplay 业务表，使改编快照与提交验证可在同一事务完成。不把剧本写进原作 objects 或属性记录。直接按目标结构建表，不引入模块存储版本协商或客户端兼容边界。

首次显式创建剧本时原子初始化当前表集及其独立空时间线；只读不初始化。时间段须在剧本创建并导入节点后建立，不能绑定源改编或其他剧本时间线。开发期结构变化可以清空并重建整个测试工程，不编写旧数据迁移流程。正常只读操作不初始化写入；正常业务中的节点删除仍须产生可解释的失效范围诊断。

持久化需要：screenplays、script_timelines、script_episodes、script_acts、script_structure_entries、adaptation_spans、script_segments、script_units、script_blocks、script_entity_usages、script_writing_bases。完整模型输入输出继续存入现有任务档案，表内保存引用和摘要，不保存密钥。

## 9 验收约定

### 9.1 自动化与界面验证

必要测试覆盖业务约束而不是机械复制实现：

- 五级选择、折叠过滤、父子去重、单节点范围和交错容器范围。
- 边界屏蔽、全部屏蔽、删除、倒置、内部移入移出及范围重叠。
- 场表采用后修改、正文保留、场次 ID 稳定、显式删除／拆合处理。
- 修改一场不使其他无依赖场失效；前场结尾改变能影响实际依赖的后场。
- 生成期间用户改本场拒绝旧输出；改别场无关字段不拒绝。
- 批量单场失败／取消不丢已提交场，不自动重开请求。
- 集幕单一归属、非法跨域引用、拖动重排、结构页与主表一致。
- 从空库直接建立当前结构；正常业务读写保持原作与剧本语义分离，只读打开无初始化写入；不测试旧数据保留或兼容。
- UI、CLI、MCP 使用同一操作和参数合同；纯文本导出保持内容与顺序，JSON 导出保持身份、关联与顺序；本阶段不承诺导入。

Qt 手动验证连续选区、场表编辑、正文焦点和选择、修改目标提示、屏蔽可见性、任务停止、重启恢复。状态派生正确性优先在业务测试验证，不为每个文案写脆弱 UI 测试。

### 9.2 最小真实模型验收

使用新隔离工程和单独结果目录，采用合成短原文及一个包含若干事件的改编时间段，目标输出2至3场。覆盖拆场、一次场表修改、单场生成、剩余场批量生成及一次局部正文修改。

以上是场景覆盖，不要求固定数量的模型轮次。验收前登记提示／模型／参数版本、允许的外部观察时长和费用预算；记录每次实际请求。仅覆盖本轮变化，不扩大到全书或固定多篇样本。

验收通过条件：场表和正文均来自真实输出并经 Operations 自动入库；身份与绑定正确；局部修改不覆盖其他正文；无效提交保存诊断；任务输出、usage、终止原因和逐场实际写入可追溯。手工修补结果不能算真实生成通过。

缺凭据、失败、截断或未完成时保存可得证据，报告“真实验收未通过／未完成”；本轮不自动重试。产品任务不设总时限，外部验收观察预算不能写成产品截止。

### 10.2 追加导入补充（2026-11-03）

用户要求剧本能继续追加时间点。新增 `append_screenplay_timeline(screenplay_id,moment_ids,expected_timeline_revision,expected_adaptation_revision,reason)`，CLI为`screenplay-timeline-append`，MCP同名工具；与会更新来源字段的显式`import_screenplay_timeline`分开。

追加仅把新ID节点和必要状态按源当前顺序放到剧本本地末尾，保留既有ID、字段、排序及全部创作内容。重复节点／状态跳过；只为必要祖先增加新子引用。若旧属性记录与导入基线完全相同，且源只将其开放结束边界关闭到本次新增节点，允许随追加补齐该结束边界，摘要`boundary_updates`逐项说明；实际值、起点、本地区间或类型语义冲突均原子拒绝，不静默结束用户本地状态。

界面已有副本显示“追加导入时间点”，候选标记“已导入”，容器仍可选以带入新子项。成功追加保留范围选择、段落、当前场、正文和折叠状态，按最新副本重新预览。普通统一助手追加后取消，已完成操作与正文也保留；取消摘要按已成功剧本工具写入记录，不以原作graph revision未变误报“无入库变更”。


本轮追加最小真实验收：1个统一任务、4次服务请求、94,868 tokens，20万token与180秒观察预算内，17.3秒完成，无另开任务／自动重试。仅追加操作由真实模型触发，既有节点、场表和正文明确标记为合成fixture；验证新点位于末尾、旧节点顺序／属性／段落／场表／正文不变，原作和源改编不变。相关回归72项及Ruff、Pyright通过；普通助手追加后取消、保留完成结果及同常驻会话继续由真实Operations+mock运行时回归验证，不冒充真实模型取消结果。记录见[追加验收摘要](../artifacts/screenplay-append-live-20261103/acceptance-summary.json)。
