状态：本文记录路线与已交付边界。截至 2026-10-18 的近期主线见第 2.1 节；人物/事件分析与分类检索已交付，反馈引导 agent v5 的 26 项原始候选经用户逐项确认后采纳 25 项，原产品 v0.3 局部补全顺延。已阅读前版计划，核对主要公开仓库，并检查 DNE 提取源码、Narra 知识模型源码、Continuity Studio 架构文档；没有运行这些项目、完成完整代码审计，或测得本系统的复用收益。

## 1. 本版的决定

主线保持不变：

**原文与证据 → 人物/事件分析工作台 → 叙事组织、分类与组合检索 → 有界 agent 供稿与分级审核 → 局部补全、场景交付与受控创作。**

最终工作分工是**模型承担大部分**：阅读、抽取、校验、初审和常规接受由模型完成，人工只处理模型标记为薄弱、低置信、证据冲突、范围不明或高风险的环节。现阶段仍以「模型提案、人工接受」为验收门槛；置信度校准、自动接受阈值、抽样复核和回滚机制建立之前，不把这一目标写成已实现能力。

变化在于：每个阶段都有明确的上游复用对象、目标模块、必要语义改造、验证样例和退出方案。复用核验计入该阶段，不设独立的长期调研阶段。

### 1.2 这次源码核查对路线的直接影响

**DNE：** 已查看的 `apps/api/ingestion/entity_extractor.py` 用结构化对象提取实体、关系与状态变化，但该文件的输出结构没有逐条原文证据跨度、故事有效时间或人物认知范围；实体默认 `alive=True`、`status="active"`。该函数也对传入文本使用 `chapter_text[:80_000]`。[R2] 因此，不能把这些输出原样当成本系统事实。首版必须增加精确证据定位、未知值、时间／认知范围与输入覆盖检查。对单个函数的观察，不等于断言上游完整流水线必然丢失长文本。

**Narra：** 已查看的 `src/models/knowledge.rs` 同时包含领域对象、SurrealDB 类型与数据库操作，知识创建也有“已知／初始知识”的默认值。[R4] 因此默认采用领域设计和测试场景，不做逐行跨语言翻译；未知提取结果不得自动成为人物已知信息。

**Continuity Studio：** 当前文档区分永久实体身份与单次供应商请求的参考标签，并描述版本、序列状态、验收和导出；其 README 明确说明直接视频生成、自动像素检查和最终组装并非已完成能力。[R5][R6][R7] 因而产品 v0.4 交付场景契约和资产引用，不把完整视频流水线写入承诺。

**许可：** Narra 仓库标注 MIT；Continuity Studio 的 LICENSE 为 Apache-2.0；Z3 的 LICENSE.txt 为 MIT。DNE README 标注 MIT，但本次查看的根目录未见独立 LICENSE 文件。DNE 代码／提示词分发前须核实完整授权材料；未完成时只作流程参考并独立实现，不使交付依赖取得授权。[R1][R3][R5][R8][R9]

### 2.1 当前交付与近期主线（2026-10-18）

本轮把产品重心从提取合同细节转到人物、事件和故事结构分析。核心模型和 Operations 聚合查询提供底层能力；用户通过「人物与事件地图」浏览人物特点、关系、状态、相关事件、参与者、前后状态、证据、故事线和分类。组合检索支持关键词、原文、人物／地点／物件、资料类型、叙事类型、审核分类、状态与故事线筛选；结果按当前修订展示，覆盖提示明确不代表全文完整分析。推断类分类和故事线仍须候选审核后才成为正式资料。

近期主线按用户可见能力推进：

1. **人物与事件分析工作台（本轮交付）**：人物档案、关系与事件互链、事件前后状态、证据和覆盖提示；UI 与 CLI 只调用 `Operations`，浏览不改变正式修订。
2. **叙事组织、分类与组合检索（本轮交付基础浏览）**：按原文查看叙事事件分类表，浏览故事线及其事件，提交自定义分类候选并组合查询。事件分类可直接描述模型输出；人物分类、关系、故事线等解释由人审核。
3. **agent 供稿与分级审核（v5选择性采纳）**：UI 可选择原文范围与证据检索轮数（用于从 research 转入 draft），启动／刷新／取消分析，并查看阶段与剩余量、预检诊断、工具动作、usage、暂存工作集和候选预览；还可针对待审候选提供反馈，开启只读继承草稿的新 run。新任务默认不设总模型轮数、总 token 或总时长上限，工具调用不限次数；单次请求超时与单轮响应容量仍是服务参数。草拟与预检修正持续到 ready/通过，提交阶段保留执行；候选须在「候选审核」由人决定，不会由 agent 自动采用；这是当前门槛，最终目标是模型按置信度承担常规接受，人工只复核低置信与高风险项。v5 的原始 26 项与用户选择性采纳的 25 项分开留痕。

## 3. 最小技术结构

### 3.1 架构边界

```text
单一工作台／薄 CLI
        │
        ▼
应用服务：提出候选 → 检查 → 提交修订
        │
        ├─ 原文、实体、证据与差异审核
        ├─ 时间、状态与静态检查
        ├─ 局部补全／外部干预
        └─ 场景与资产接口
        │
        ▼
SQLite：唯一正式叙事数据源

LLM／可选 Graphiti → 候选或检索结果，不直接写正式事实
Z3 → 检查结果，不负责猜测缺失故事设定
资产系统 → 资产目录与固定版本，本系统保存绑定而不重复管理资产生命周期
```

默认 Python + Pydantic + SQLite + Qt Quick（Streamlit 浏览器入口已于 2026-10-20 停用）。它们是本计划选型，不要求上游项目迁移到此技术栈。已有本项目界面可用时沿用，不同时维护第二套 GUI。一个包内的模块足够，不拆微服务，不做通用插件注册中心，不同时建设 REST、GraphQL 和 MCP。

一个供应商适配器、一个有界后台执行器，首版串行。任务、模型结果和审核决定持久保存。SQLite 写入采用短事务；外部调用期间不持有写锁。界面重运行不等于重新调用模型。

代码目录随需要出现，不提前创建空框架：

```text
src/narrative/
  models.py        # 最小领域对象与变更协议
  store.py         # SQLite、修订、迁移与短事务
  service.py       # 核心操作，界面和 CLI 共用
  extraction.py    # 分块、证据定位、候选提取
  llm.py           # 单供应商、提示词版本、运行记录
  state.py         # v0.2
  checks.py        # v0.1 起积累
  authoring.py     # v0.3 补全；v0.5 复用
  production.py    # v0.4 场景与资产契约
  ui.py / cli.py   # 薄入口
```

### 3.2 只统一三个跨模块契约

| 契约 | 必须表达 | 引入时机 |
|---|---|---|
| ChangeSet | 基础修订、候选操作、来源、证据、假设、涉及范围、运行 ID | v0.1 |
| Diagnostic | 规则 ID、严重程度、判定、对象／时间、依据、检查覆盖、建议 | v0.1 |
| ScenePackage | 叙事修订、场景边界状态、必须满足的约束、资产需求与固定绑定、缺口 | v0.4 |

原著提取、人工编辑、补全和创作都使用 ChangeSet。接口首先是普通 Python 函数，不为三个契约单独开服务。

ChangeSet 使用结构化操作与稳定 ID，不接受模型提供的 SQL、任意 Python 或未经批准的工具调用。原著和检索片段按资料处理，不能以其内容修改系统权限、执行计划或验证策略。

### 3.3 简化实现，不丢失语义

| 语义 | 首版最低要求 |
|---|---|
| 身份 | 实体 ID 与姓名、别名分开；合并可纠正 |
| 证据 | 固定原文版本、哈希、规范文本映射、字符范围、原句 |
| 来源 | 原著提取／规则推导／创作补充／制作决定分开 |
| 认知 | 世界事实／人物主张／人物认知分开；不确定时待核验 |
| 状态 | 候选／接受／争议／取代分开；未知不设为 false 或正常 |
| 时间 | 故事有效时间与叙事披露位置分开；支持未解析 |
| 修订 | expected_revision、防重复提交、修改记录、备份恢复 |
| 检查覆盖 | 一致／冲突／信息不足／未支持不能混为“通过” |

首版不建设通用双时态数据库和通用事件溯源平台。需要的原文证据和审计记录从首版开始保留，后续通过有版本的迁移扩展。

## 4. 复用准入：嵌入阶段，而不是增加一个阶段

每个准备复制、移植或依赖的单元，都在同一份复用记录中留下：

| 字段 | 内容 |
|---|---|
| 来源 | owner/repo、固定 commit／release、具体文件或公开 API |
| 方式 | 直接依赖／复制后改造／行为移植／仅作设计参考 |
| 许可 | 适用许可证、版权、NOTICE、所含第三方素材或模型的独立条款 |
| 差异 | 我们保留什么、改变什么、刻意不兼容什么 |
| 证据 | 本地测试、真实联调结果、未支持项 |
| 退出 | 移除该上游后，哪一项小实现或人工路径继续工作 |

计划采用的候选与已实际复制的代码应明确区分。正文附表是初始选择，不虚构已固定的提交号或测试结果。

**复用的完成标准不是“研究了一个仓库”，而是至少产生一个已验证的本地模块、测试案例，或明确避免错误设计的决策。**

小单元首次核验通常控制在 0.5—1 个开发日，复杂候选最多给约 2 个开发日的试验预算；这些是开发管理上限，不是本次回答的工作承诺。超出后默认退回参考设计或最小自研路径。复用评估预算已经包含在相关阶段工作量中。

不为模型对象引入另一种运行时；不为提示词继承整个 Web 平台；不为几个规则搭建工作流服务。代码复用后保留所需版权、许可证、适用 NOTICE 和修改说明。改写成另一语言也要记录派生来源。未许可代码不通过“让模型改写”绕开授权。

## 5. 产品 v0.1：Narra 模型参考 + DNE 提取审核工作流

### 5.1 可见成果

导入一章，查看实体与候选断言，点击定位原句，修正未知状态或人物说法，接受记录，重启后继续核验。

### 5.2 复用任务

| 任务 | 上游输入 | 本地交付 |
|---|---|---|
| R-N01 | Narra 人物、地点、关系和知识模型 [R1][R4] | Entity、Assertion、KnowledgeRecord 的最小字段与行为测试 |
| R-D01 | DNE `entity_extractor.py` 的结构化提取组织 [R2] | 以已批准类型提取候选的函数；去除数据库和具体供应商耦合 |
| R-D02 | DNE Schema 建议、字段前后差异审核流程 [R3] | 新字段建议列表、候选差异表；不自动修改 SQLite 表结构 |

首版使用固定核心类型 + `properties` 扩展字段。LLM 可以建议新属性或子类型，不能直接创建一套新的数据语言。结构化字段经核验后才进入可执行规则。

DNE 许可未明确前，不复制提示词或源码；按本项目输入输出独立实现相同用户流程。Narra 的模型设计同样只保留与当前功能直接相关的部分。

### 5.3 必须补齐的改造

- **证据定位：** 模型返回原句及所在分块，程序在固定原文中定位跨度；重复原句有多个候选时要求更多上下文或人工选择，不默认取第一个。
- **输入覆盖：** 按稳定分块 ID 处理，记录已处理、失败和遗漏的范围；禁止静默裁剪输入。重叠分块允许去重，但不能合并不同时间发生的相似事件。
- **未知处理：** 未提及存活、所在地、关系状态时保留未知或不产生断言，不使用上游的肯定默认值。
- **认知范围：** “甲说乙死亡”先成为甲的发言内容，不直接成为乙死亡的世界事实。
- **修订安全：** 候选只能对其 expected_revision 提交；名称对齐修改有记录；重复点击接受幂等。

### 5.4 验收

一章手工闭环必须先可用，再连接一个真实模型。正式的原著型断言全部有可定位证据；定位率不冒充语义准确率。至少一次真实 API 调用成功，另有失败、超时、重复提交、重启与恢复测试。

固定测试包括重复引文、化名、说谎、未提及存活状态、长文本末尾关键事实。文本覆盖测试可以用合成分块响应完成，真实模型质量另测。

**退出路径：** DNE 代码无法独立运行或授权不满足，则采用本地小型提取函数；模型质量不足则保留手工整理与候选审核，不开启自动接受。不能因复用失败延迟原文阅读和证据工作台。

**不做：** 图数据库、向量库、多代理、动态图谱画布、全书自动实体合并。

## 6. 产品 v0.2：状态时间轴 + 可解释静态检查

### 6.1 可见成果

查询交接前后钥匙持有者，查询人物当时知道什么；改变事件时间后出现具体诊断，并能定位原文依据。

### 6.2 复用任务

Narra 的知识获得方式、来源人物、关联事件和历史记录作为设计参考。[R4] 不把默认“知道”迁入提取模型，不把向量偏移分析当因果推演。[R1]

Inform 等交互叙事项目仅作为动作前置条件和效果设计的候选参考，不安排额外整库接入任务。先实现五类动作：移动、交接、换装、受伤／处理伤势、告知信息。

第一批检查使用普通 Python／SQL。Z3 只在需要联合求解时间或资源约束的实际案例出现时启用，不改变其余应用结构。Z3 支持可满足性检查和冲突核心，但默认冲突核心不保证最小。[R9][R10]

### 6.3 检查与规则范围

| 规则 | 行为 |
|---|---|
| REF／EVID／REV | 引用、证据与修订错误阻止正式提交 |
| TIME | 确定时间先后矛盾、时长约束冲突；未定顺序返回未定 |
| STATE | 同一范围内显式互斥状态冲突；按属性策略判断 |
| ACTION | 前置条件明确不成立则冲突，缺少前提则信息不足 |
| KNOW | 使用未记录获取路径的信息通常是警告；只有在明确封闭范围内才能判硬错 |

时间轴先是可排序事件表和状态差异视图。插叙只改披露位置，不改变故事时间。属性延续有显式策略，不把服装、伤势、所在地无限自动延续。

原著矛盾作为争议证据保留。可以阻止将矛盾状态发布为确定答案，但不能拒绝保存原文或删除冲突证据。

### 6.4 Z3 小范围接入契约

若启用：仅由程序把批准的规则编译为约束；不执行 LLM 生成的求解脚本。每条约束有来源 ID。返回 sat／unsat／unknown／timeout 及覆盖范围；sat 只表示所编码约束可满足，不表示文学合理或现实唯一。unsat core 映射回叙事对象，不能称为自动得到的最小冲突集合。

插件未启用或规则未支持时返回未分析，而非通过。纯状态查询不依赖求解器存在。

### 6.5 验收

20 个状态问题，包括未知与冲突；20 个应报警、20 个不应报警案例。固定修订与规则版本下结果一致，查询和硬检查不调用 LLM。

采用上游设计的每个字段至少有一条本地行为测试；不能把上游测试全部成功当作本系统成功。若接入 Z3，增加可满足、不可满足、不支持与预算中止等分支测试。

**退出路径：** 复杂规则不支持时缩小自动检查范围并明确标注。Z3 接入问题不阻塞基础状态和 Python 检查发布。

## 7. 产品 v0.3：复用候选审核机制完成局部补全

### 7.1 可见成果

选择一段空白，指定必要字段与前后锚点，得到两套候选事件，比较状态差异和假设，采用或拒绝，能够回退。

### 7.2 实现主线

复用 v0.1 的 ChangeSet／核验界面和 v0.2 的状态／检查。先查已导入原文中的实体、别名、事件和关键词，显示资料覆盖与未读范围。再生成限定事件模板的候选。

每个候选引用固定父修订，先用少量完整逻辑副本作为沙盒。不建设通用 Git 式合并，不同时维护第二套世界权威数据库。

验证范围是所选区间、指定锚点和已编码规则。未形式化的人物动机、叙事质量属于语义评审，不能伪装成确定性证明。

### 7.3 Graphiti 的选择性试验

Graphiti 提供时间知识图谱与检索，并需要相应图后端；其部署和存储边界并非本地核心中一个无状态函数。[R11] 本阶段不强制接入。

只有基准检索在保留样本持续漏掉关键证据，才安排同数据集对比：

| 指标 | 比较方式 |
|---|---|
| 原文证据召回 | 同一问题、同一原著片段，有人工答案 |
| 实体误合并 | 不以返回更多实体当作质量提高 |
| 人工核验成本 | 每千字审核时间，配合正确率观察 |
| 运行成本 | 调用量、耗时、依赖、启动与恢复负担 |
| 数据隔离 | 分支／修订过滤、能否从原始资料重建、卸载后的可用性 |

项目可把“保持正确率且审核时间下降约 20%”设为试验目标，不是既有性能结论；小样本一次波动不足以采纳。没有可重复收益则关闭试验，不开发两个长期后端。

若采用，Graphiti 只提供检索或候选，正式库仍唯一。索引带原文／修订／分支范围；不得把被拒绝的创作未来检索给正式人物。它的时间字段不能静默映射为本系统全部故事时间语义。

### 7.4 验收与退出

五个固定补全案例：可补全、违反前锚点、违反后锚点、资料不足、过期修订。原著、推导和创作来源保持可见；未选方案不污染正式历史或人物知识。

Graphiti 无法部署或收益不足，继续使用结构化／关键词检索。不能把查询后端选型变成补全功能的前置阻塞。

## 8. 产品 v0.4：Continuity Studio 契约参考 + 资产桥接

### 8.1 可见成果

选择场景，查看入场／出场状态及必要期间约束，匹配人物形象和道具，显示缺失资产，导出固定版本 ScenePackage。

### 8.2 复用任务

从 Continuity Studio 的文档和独立实现中研究：

- 永久人物／资产 ID 与一次请求中的上传顺序、参考标签分离。
- 场景或序列 START／MID／END 状态、审核与锁定。
- 上游版本改变后的下游复核。
- 一个规范场景状态生成不同消费端输入，而不是每个供应商维护自己的世界事实。

优先入口为 `ARCHITECTURE.md`、`docs/ARCHITECTURE.md` 与文档指出的 `server/sequence-workspace.ts`；后者是待阶段核验的源码入口，不表示已经审计。[R6][R7]

首版只需要入场／出场状态；MID 或关键帧状态在确有镜头需求时增加。采用的物理边界连续性不等于所有镜头机械沿用上一镜头结尾，仍按故事时间、场景转场与分支查询。

### 8.3 必须保持的三层分离

1. 预期叙事状态：这段故事应该成立的内容。
2. 候选产物观察：从图片／视频中观察到的内容，允许不确定。
3. 已验收产物：选用了哪份文件和哪些偏差。

采用一个视频不能自动改写世界事实。需要改变故事时，另提交 ChangeSet。

### 8.4 资产接口

资产系统负责文件、版本、发布与媒体生命周期；叙事核心负责需求和绑定。先实现：列出候选资产、解析固定引用、检查已声明属性。可用本地 manifest 模拟外部接口，但要标明它是测试适配器。

参考 OpenAssetIO 的实体引用／解析分工，不声称本地 manifest 已兼容 OpenAssetIO。该项目提供连接宿主与资产管理的 API，本身不是资产管理产品。[R12]

ScenePackage 记录 schema_version、branch_revision、场景故事区间、实体状态、资产引用与哈希、约束、制作决定、未解决事项和检查覆盖。请求标签与上传序号仅存在于下游适配结果。

### 8.5 验收与退出

三个场景可导出，由独立消费者脚本读取。缺失资产、固定版本不匹配、明确的外观冲突可定位。新资产发布不会改变旧包。

核心必填引用不满足时阻止正式导出，但允许带缺口的草稿预览。早期任意上游修改后可保守标记所有导出待复核；细粒度失效以后再做。

真实资产系统未完成时，继续交付本地清单和场景包，不重复做资产平台。只有实际接通消费者才称为完成联调。

OpenTimelineIO 留到真实剪辑交付需求；它表示剪辑结构和媒体引用，不取代本系统的故事时间轴。[R13]

## 9. 产品 v0.5：Concordia 分工参考 + 有界创作

### 9.1 可见成果

输入“航道中断三天，不增加新的能力体系”，查看少量角色行动与结果候选，在一个关键选择处暂停，采用一小段后继续。

### 9.2 实现

新增 Intervention 与 CreativeIntent，但复用 v0.3 的任务、候选、沙盒、检查和采用界面。

Concordia 公开设计中由角色提出行动意图，Game Master 处理观察和结果。[R14] 本项目采用这个分工：

```text
创作者激励 → 相关人物的视角上下文 → 行动提案
        → 世界规则检查与结果候选 → 有限试演
        → 人物动机／创作目标比较 → 选择与提交
```

默认先用普通函数与有限模型调用实现，不默认安装完整 Concordia。若后续多角色交互确需其调度，再建立仅返回候选、不得直写正式库的适配器。

每次干预默认两个候选，每个 3—5 个事件；新增实体、模型调用、探索跨度均有预算。探索未来不能进入当前人物记忆；角色上下文不包含作者的全知秘密或未采用结果。

世界完善分为“补充未定义设定”“世界内真实变化”“修改已锁定设定”。第三种需明确变更权限或另开分支，不能作为自动补全偷偷采用。

### 9.3 验收与退出

三组干预案例走完整流程。达到预算、规则冲突、需要修改锁定事实时暂停。硬检查与文学评价分别呈现。

Concordia 接入无明显收益则保留函数式控制，不同时接 Ensemble 或第二套代理引擎。创作质量不稳定时保持探索／导演辅助模式，不开启无人值守长期演化。

### 10.3 迭代节奏

每 2—3 个开发日争取演示一个完整用户操作。当前阶段排到具体任务，下一阶段只细到接口和验收，后面保留里程碑。阶段结束复核是否真正省力、是否可恢复，再决定下一步。

复用探索已超过预算且没有可运行单元时，作出“不采用”也是有效结果；但必须继续完成用户路径，不能交付只有调研结论的版本。

## 11. 测试、发布底线与成本

### 11.1 固定材料

自编可分发测试故事 + 3—5 章有权使用的中文作品；真实材料拆开发片段与保留片段。人工标注约 50 条关键事实、20 个状态问题、20 个应报警和20 个不应报警案例。它们是初始规模，不是容量上限。

模型评估报告同时给出样本数、正确数、遗漏数、误合并、来源／认知范围错误，以及每千字审核分钟数。可沿用准确率 90%、关键事实召回率 80% 的初始观察目标，但不把小样本成绩作为全书自动建库保证。

### 11.2 两类测试分开

确定性测试离线运行：类型、引用、证据、状态、修订、幂等、恢复、资产契约。模型响应回放仅测试程序如何处理输入，不能冒充真实模型联调。

真实模型评测在提取流程、提示词、模型或阶段验收改变时触发。保存模型标识、输入哈希、提示词版本、参数、原始响应、调用用量和失败；不可得的指标明确标注。

上游自带测试是参考，不能替代中文长篇样本、时间／认知语义和本地交易行为的测试。

### 11.3 发布底线

**必须阻止发布的问题：** 数据损坏；证据错位；把未知当事实；把人物主张当世界事实；未采用候选污染历史；过期提交绕过复核；没有接通的接口却返回成功。

提取效果不足时允许以人工辅助版发布。复杂规则未覆盖时明确显示覆盖范围；不能用“所有检查通过”掩盖未分析部分。

每项功能同时验证正常路径、错误／资料不足路径、重启／版本变化路径。涉及外部系统时，还需至少一次真实联调证据。

### 11.4 运行与安全

任务先落库再执行；接受采用短事务；重启将未完成任务标记中断。取消停止后续工作和采用，供应商侧取消能力单独验证。本地幂等不保证外部供应商只收费一次，超时后不无限盲重试。

密钥只在凭据或本地忽略配置中保存；导出排除密钥。原文与响应默认留在项目，调用外部模型时显示发送范围。导入文件和资产引用限制在批准路径内，外部代码在隔离环境检查，不直接执行来源中的脚本或指令。

性能先记录基线，不先造性能平台。数据量使全量检查妨碍工作时才增加增量依赖；查询、模型调用、媒体处理分别计时。
