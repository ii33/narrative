# 叙事 · 证据工作台

公开仓库仅包含代码、项目文档、测试及合成样例；真实作品文本、数据库、运行输出和部分本地验收夹具不随仓库分发。首次使用请先阅读[公开仓库范围与资源依赖](docs/PUBLIC_REPOSITORY.md)。

当前主入口是 **叙事图工作台（Schema v7）**：以统一节点表示人物、群体、物品、地点、事件和场景，
属性用带原文位置的可审核记录表达。图里只有节点、语境、时间轴、来源顺序和属性记录——
断言、关系图、组织树、故事时间偏序已删除，逻辑事件图留到第二阶段重建。UI 只通过 `Operations` 访问业务能力。

数据与语义约定见 [数据模型](docs/DATA_MODEL.md)。阅读顺序按原文位置算（章节序 + 字符位置），
同一事件内的多条披露再按各自的原文位置排先后。节点编号**每种类型各一套**（`P1`、`I1`、`E1`），
`P3` 和 `I3` 之间没有先后——编号只用来看「这是同类里的第几个」。

工程库不迁移、不覆盖：**只有当前 schema 版本能打开**，旧版本文件在工程列表里标为「不兼容」，
可用「清除不兼容」一键清掉（无法读取的文件只报告，不删除）。

**目标工作方式（尚未实现）：** 模型承担大部分阅读、抽取、校验、初审和常规接受；人工只处理模型标记为薄弱、低置信、证据冲突、范围不明或高风险的环节。当前版本仍是「模型提案、人工接受」：置信度校准、自动接受阈值、抽样复核与一键回滚尚未建立，因此不把目标写成现有能力。

当前唯一入口是 **Qt Quick 原生桌面窗口**；Streamlit 浏览器入口已于 2026-10-20 停用，代码与测试保留但不再维护。Python + Pydantic + SQLite，单机单用户；原始附件未修改。后续开发依据 [开发计划 v0.2](docs/PLAN.md)。

## 启动

Windows 可直接双击根目录的 **`start-desktop.cmd`**，打开原生 Qt 窗口。首次使用需在项目目录安装桌面依赖：

```powershell
uv sync --extra desktop
```

也可在 PowerShell 中启动：

```powershell
./start-desktop.ps1
./start-desktop.ps1 -Project my-novel
```

`start.cmd` 仍保留为兼容入口，会提示 Streamlit 已停用并转启原生窗口；`narrative ui` 命令现在会明确报错，不再启动浏览器。

开发时修改业务模块后，等待活动提取结束，再重启桌面窗口；只刷新界面不能保证已导入的 Python 模块更新。

### 给程序和模型：MCP / CLI

同一套能力有两个门：命令行给人，MCP 服务给模型。两者都落在 `narrative.tool_api` 的同一张
工具表上——读节点、场景、事件在某个阅读位置的状态与统计，也能补录、更正、失效、修订节点、
审核候选、跑提取。没有窗口状态参与，只有工程文件。

```bash
narrative nodes --project P --type person      # 节点列表（带分类计数）
narrative scene 28 --project P                 # 这一场结束时各方是什么状态
narrative event 34 --project P --json          # 读到这一步时的状态
narrative stats --project P                    # 统计
narrative tool list                            # 全部工具（与 MCP 同一张表）
narrative add-property 7 state 神色平静 164 --project P
narrative-mcp --project P                      # MCP over stdio
```

完整工具表、`cut`（阅读位置）的含义和 MCP 客户端配置见
[给程序和模型的接口](docs/AGENT_API.md)。

### 原生桌面界面（Qt Quick）

准备桌面依赖并启动原生窗口：

```powershell
uv sync --extra desktop
uv run narrative-desktop --projects-dir data/graph-projects
```

Windows 也可在依赖安装后双击根目录 `start-desktop.cmd`；它会打开可见的 Qt 窗口并在后台记录渲染诊断。首次安装或升级桌面依赖仍需在项目目录运行 `uv sync --extra desktop`。启动脚本要求 `.venv` 中已有 `pythonw.exe`，缺少时会提示先安装依赖。

也可在启动时打开项目目录中的现有工程：

```powershell
uv run narrative-desktop --projects-dir data/graph-projects --project my-novel
```

窗口分两级：

```text
启动 → 工程列表（+ 全局设置） → 打开工程 → 操作界面
```

**工程列表**是唯一入口：列出目录下的工程（可用 / 不兼容 / 无法读取）、新建工程、清除不兼容文件，
右侧是**全局设置**——模型服务地址、模型 ID、密钥变量、推理强度、token 预算与超时。
全局设置存在应用级配置库（默认 `~/.narrative/provider-settings.sqlite3`），不进工程库；
工程没有单独配置时沿用全局值。

**操作界面**主页是**数据浏览**：左侧按分类（人物 / 群体 / 物品 / 地点 / 事件 / 场景）列出节点及数量，
中间是按阅读顺序排的节点列表（编号按类型各成一套），右侧是详情、原文与类型修订/撤回；搜索在当前列表内即时过滤。
右侧属性按**大类**分组（人物：基本信息 / 外貌 / 身份与经历 / 能力与身体状态 / 持有与使用 /
关系 / 心理与意图 / 其他），组内**一个方面一条线**：同一方面（`cultivation` 与
`cultivation_stage` 算同一方面）的披露按阅读顺序排列。**失效的披露不显示**——撤回不删行，
但它不再出现在属性里，也不带任何「已失效」的标注。行首显示这条方面仍然有效的值；
同一方面跨两个大类时只有一个算当前，另一个标「（历史）」。每条记录带作用域标签、章节与位置。顶部两行条件都交给后端算：**事件等级**（场景／事件，
默认场景，读完一个场景=读到它最后一个事件）、**全部显示／按时间显示**（列表是否跟着收窄）、
**阅读位置**（下拉 + ‹ › 步进 + 最新）、**相关节点**（默认勾选，只看这一步：场景连同它包含的事件，
事件连同它所属的场景，再加参与者）。切换场景／事件粒度停在同一个阅读位置
（场景换成它最后一个事件，事件换成它所属的场景），不会跳回最新。
切换后属性区随之显示"读到那里时"的状态。
点分类标签把记录移到别的大类，「分类表」按节点类型改名、增减大类，
「补录」人工加一条披露（预检通过即生效，披露事件默认是当前阅读位置）。「编辑节点」打开节点编辑器：改名称/类型/别名/说明，
逐条**更正**（追加新记录并撤回原记录，两半一起落）或把整条属性**设为失效**（原因必填，失效不删行）。
编辑器和浏览区都只显示现在站得住的属性；失效的披露不显示（记录仍在库里，撤回不删行）。
停在「最新」时编辑器看整份历史；按阅读位置看时只列那一刻已读到的记录，改动仍然立即生效
（落在你选的披露事件上，落在窗口之外会提示）。
失效是自动的：一批记录被接受时，更早的旧值在同一个事务里就被标成失效（从取代它的那次披露起），
不需要额外点一次。人只需要判「这条从来没有算数」（读错了），那走更正。
同一属性可以同时出现在两个大类下（`state = 脸色铁青`
在外貌、`state = 身受重伤` 在能力与身体状态），每条记录也能单独移动。
别的节点指向本节点的记录（例如手镯的 `holder`）以**反向引用**列在页面下方，是同一份记录的第二个入口。
另有五个页面：原文（导入与回查）、提取（按章提取）、属性（最近披露与披露序列）、
审核（候选接受/拒绝）、模型（本工程服务配置 + 运行记录 + trace）。
每个页面自持状态并自行订阅 `bridge`，主窗口只负责导航与状态栏。

详情栏下半部分是**节点资料**——人物、物品、地点、群体、事件、场景用的是同一套。一份资料是一张
**资料卡**：标题、详情、若干张带说明的图片，加上**生效时间**和**失效时间**（空表示不限制）。它和属性是同一类东西——「从这一步起成立，到那一步起不成立」——所以浏览时同样
**只显示当前阅读位置上有效的卡**，默认**折叠成一行标题**，点标题才展开；别的时间点上的只报个数，
免得让人以为资料丢了。

时间点按**粒度分级**挑：一列一层，先场景再它底下的每个事件——层级表在后端
（`browse_view.MOMENT_LEVELS`），父子关系看谁把谁列在 `events` 里，所以再往上加「卷/章」
或往下加「一个事件里的动作」只是往那张表里插一行，界面会多出一列。编辑资料卡时图片也在同一张表单里
加：可以一次选多张，每张下面写说明，保存时一起拷进工程。

资料不是披露：没有原文引文，所以不进属性记录，而是存在工程旁边
`<工程>_material/<节点编号>.json`，图片原样拷进 `<节点编号>/<资料编号>/`（不引用你选的原路径）。
Windows 上删不掉页面正开着的图片，所以删除是尽力而为：记录立刻消失，文件在下一次打开这一页时清掉。
缩略图只有 120px，点一下看大图，说明在大图下面。

右上角的**协作者**是常驻面板：问图里的事（谁在场、某个编号是什么、这条记录为什么失效），
它自己调读工具再回答，用过的工具一行行列出来。回答按 Markdown 渲染（它也可以给一段 HTML）；
输入框左边的「图」可以附一张图片一起问——图作为内容块送给模型，不是把路径写进正文。它**只能读**——工具白名单里没有任何写操作，
接受候选、删除记录、改资料卡仍然由人来做。会话按工程保存，切页面不丢；「清空」换一个话题。
同一套循环也可以从命令行跑（`narrative tool call` 是它的手），区别只在有没有人看着。

属性分类的完整约定见 [`docs/PROPERTY_CATEGORIES.md`](docs/PROPERTY_CATEGORIES.md)：
大类只管显示位置，与 `scope`（世界／认知／声称）各管一件事；移动分类不改变取值、
披露顺序和原文引文。属性名可以改（节点编辑器里每条属性右边有「改名」），改名是读时别名——
取值记录不改写、定义跟着搬到新名字、撤回即恢复原名；把两个名字合成一个方面是「合并」，
需要确认含义相同后再做。

正式数据只会在候选页经过人工接受后进入图。模型设置按供应商分别读取并保存；
切换供应商只载入该供应商的配置，不覆盖其它供应商的自定义模型；密钥值仍由环境变量提供。

首次操作建议：

1. 在首页创建有独立文件名的作品工程。
2. 在「原文与证据」粘贴或导入章节文本；不同章节以不同标题保存。
3. 在「提取」配置服务、选择来源并写明分析目标。轨迹展示实际阶段、工具观察、草稿、预检与请求用量；暂停在请求边界生效。
4. 在「提取成果」检查每项证据和范围，再明确接受或拒绝；也可将待审候选连同修订意见交给 Agent 生成独立子候选，父候选保持原状。
5. 接受后，在「分析检索」按人物、物品、事件、地点或场景浏览直接断言；从中心节点按 1–3 层展开 Ops 返回的邻域与推导路径。路径会标明边方向和角色，不会伪装成一条直接事实。
6. 「资产库」汇集正式物品／地点／场景节点、已导入章节和证据锚；「原文证据」可打开不可变原文与定位片段。

“资产库”目前展示图中的正式节点、原文来源和证据锚，不代表已经接入独立素材文件管理或视频资产系统。故事时间与文本披露位置分开筛选；无法定位的边界会显示为未知，不按确定顺序补全。

v5 每个工程是独立 SQLite 文件，默认位于 `data/graph-projects/`，不进入 Git；原文和提取结果默认保留本地。运行中的数据库有 WAL 文件，请使用工作台的备份功能。

## 历史 v3／v4 版功能与数据模型说明（存档）

以下 v3 功能描述和数据模型表保留作历史参考，不代表当前 v5 页面的操作方式或 v5 数据合同。v5 工程需新建；v3／v4 库仍保留在原处，但当前工作台会显式拒绝打开或转换。本页其余描述 v3 对象（Entity、Assertion、Event、KnowledgeRecord 等）的段落同属存档。

### v3 历史功能

- 原文保存不可变版本与 SHA-256；字符位置基于 **原样解码的 Unicode 文本**，不改写换行、空白或字形，规范映射为恒等映射。位置从 0 开始，右端不包含；不是 UTF-8 字节或 JavaScript UTF-16 偏移。
- 姓名／别名与稳定 ID 分离；名称碰撞提示人工核验，不自动合并人物。
- 世界事实、人物主张、人物认知分开，未知值为 `null`；故事时间未解析时明确提示。
- 所有原著断言必须精确匹配原文哈希、字符范围和引文；重复原句手工选定位置。
- 正式提交检查修订和候选编辑版本，短事务提交；重复接受幂等，修改保存前后值，未采用候选不污染正式资料。
- JSON 编辑可修正实体引用、认知范围、时间、来源、状态和证据；类型不合法或未知操作无法提交。
- 备份／恢复包含原文、正式资料、待审／拒绝记录、修订、分块和原始提取结果。恢复只写新文件。

**检查的边界：** 当前实现全库类型与引用、精确证据、修订、推导来源、锁定修改、时间与时长、动作前提、显式状态规则和人物获取路径检查。引文是否真正支持记录、人物是否说谎和文学合理性仍须人工审核；每项诊断分别报告一致、冲突、信息不足或未支持。

## 完整核心数据模型

「资料模型」页统一管理以下对象；UI、CLI、提取器均经过 `Operations`。SQLite 仍为唯一正式数据源。完整可机读契约可在页面下载，或调用 `operations.model_schema()`；当前示例导出为 `data/narrative-model-v3.json`。

| 对象 | 语义与关键约束 |
|---|---|
| Entity | 稳定身份、类型、子类型、姓名与别名、描述和非执行扩展属性 |
| Assertion | 世界事实／人物主张／旧认知范围、值与实体引用、有效期、确定性、来源与精确证据 |
| Event | 移动、交接、观察、换装、受伤、处理伤势、告知；时间、时长、前提、多状态效果和所用命题 |
| PropertyDefinition / StateFact | 批准的属性类型与适用实体、属性延续策略、真假与未知、有效期和状态依据 |
| Relation | 有向／无向关系、确定性和故事有效区间 |
| KnowledgeRecord | 命题引用、持有人、听说／知晓／相信／怀疑／否认／遗忘、获取方式、告知者与关联事件 |
| WorldRule | 必须／禁止状态与信息获取约束；显式封闭范围，缺资料不默认硬错 |
| Scene / AssetBinding | 场景区间、约束、资产需求、固定 URI／版本／SHA-256、制作决定 |
| ArtifactObservation / ArtifactAcceptance | 产物观察与验收决定，绑定场景修订，不改写预期叙事状态 |
| Intervention / CreativeIntent | 外部激励、人物目标与显式事件／新实体／模型调用预算 |

以上 14 类对象共用 `ChangeSet`、候选版本、正式修订和备份恢复。`derived_from` 来源必须存在且无环；修改锁定对象必须在候选中显式声明 `allow_locked_changes`。原著型状态、关系、认知、事件和断言必须有精确原文证据；创作与制作来源独立标记。扩展 `properties` 仅保存资料，不自动成为可执行规则。

状态默认未知，不用 false 代表缺失。`location`、`held_by` 的动作效果明确延续到改变；`outfit`、`injury:<slot>` 和自定义属性服从显式策略：到下次改变、有界区间、仅完成时刻或未确定。有效期起点包含、终点不包含；新状态到期后不会恢复更早旧状态。告知默认产生“听说”，观察也须有明确命题；处理伤势不自动等于痊愈。未定、重叠或冲突不会强行排出确定答案。

`state_at_time` 与 `full_event_state` 返回状态、认知、关系及逐项证据、未知原因；`validate_project` 只读检查正式资料。前置条件明确不成立时不应用效果，缺少前提保留信息不足。规则只执行批准的数据条件，不执行模型提供的代码。数值与相对事件查询都使用固定修订快照。

`scene_package(scene_id, draft=True)` 导出固定修订草稿，列明缺口；正式导出要求场景区间、所需资产和支持的约束满足。资产核验覆盖清单声明的属性、版本和哈希；真实媒体内容需独立观察。场景包含入场／出场状态、约束、需求、绑定、制作决定和覆盖声明，可独立读入。此处交付数据契约与确定性实现；后续局部补全和有界创作可在这些契约上实现。

独立演示项目为 `model-complete-demo`：查询第 6 分钟，林舟穿蓝衣、左臂已包扎但未确认痊愈，沈砚持钥匙并听说“门开着”，世界状态仍明确为门关闭。第 8 分钟伤势记录到期，第 9 分钟有显式遗忘，第 10 分钟穿戴到期，均保留未知或对应态度。演示脚本 `examples/model_complete_demo.py` 只创建新项目，本地清单是测试适配器。固定资产清单与场景包在 `data/model-demo-asset-manifest.json`、`data/model-demo-scene-package.json`。

## 人物与事件地图

「人物与事件地图」从当前正式修订浏览人物档案、特点、关系、断言、状态、相关事件与证据；也可从事件查看参与者与角色、事件前后状态、关联事件和所属故事线。争议与已取代资料会保留状态标记，不会显示成无条件确定事实。人物与事件之间可双向定位。

「分类与故事线」按原文列出叙事事件分类，并可浏览已审核故事线和其中的事件。可为人物、特点、关系、事件或故事线提交附加分类候选；采用前仍须在「候选审核」确认。事件原有叙事类型描述记录的分类，人物/关系/故事线归类属于解释。

「组合检索」支持关键词、原文范围、人物/地点/物件、资料类型、叙事类型、审核分类、审核状态和故事线条件。结果显示修订、来源和证据；覆盖提示只说明已有正式资料引用了哪些章节，不代表这些章节已完整分析。检索和浏览均为只读操作。

CLI 使用同一 Operations 查询入口：

```powershell
narrative --db data/book.sqlite3 character person-id
narrative --db data/book.sqlite3 event-profile event-id
narrative --db data/book.sqlite3 search-analysis --query 钥匙 --entity-id person-id --kind event
narrative --db data/book.sqlite3 classification-table --source-id source-id
```

「有界 agent」入口可按选定原文启动分析，设置证据检索轮数以决定何时转入草拟，并查看运行阶段、阶段剩余量、预检诊断、工具动作、usage、暂存对象和候选预览。新任务默认不设总轮数、总 token 或总时长上限，工具调用不限次数；单次请求超时与单轮响应容量仍有限制，任务可随时取消。草拟与预检修正持续到 ready/通过，提交阶段保留执行；候选须在「候选审核」人工决定，不会自动接受。agent v4 在孔乙己全文上生成 1 个待审候选：9 次请求、2 个工具动作，预检无错误，16 个证据引用均可精确定位；但事件与状态时间未定，语义支持仍待人审。v1/v2/v3 均未生成候选或未完成，真实结果按版本分别保留。侧栏项目名 `kongyiji-agent-v4` 打开这次待审核项目；在「人物与事件地图」的「有界 agent」页输入 run ID `0c7b0d1a99724fe0b0f1e9d6730d23d6` 可查看候选预览，也可到「候选审核」作最终判断。当前正式资料未接受该候选。

## 事件与时间轴

新增「事件与时间轴」页。可建立演示候选，审核采用后查看钥匙交给沈砚（第 10 分钟）、交还林舟（第 20 分钟）、林舟进入仓库（第 30 分钟）。这些分钟是人工演示坐标。切换原文披露顺序时，仓库事件排在前面，故事时间保持不变。

正式使用时，可人工登记事件，或在「提取交接」调用模型提取实体、断言、状态、关系、认知及事件；新增「叙事动作」只记录行为，不自动改变状态或认知。事件继续通过同一候选审核流程采用，采用后进入时间轴；审核页按姓名显示事件参与者、动作和时间。已采用事件可创建修正候选，修改时间后重算时间轴和状态，原值保留在修订记录。

图形时间轴显示已指定的分钟坐标和区间，点击事件或从下拉框选择事件可查看证据及前后物品持有者、人物所在地；可按人物、地点、物品筛选。详情中可基于精确原文证据提出事件先后或状态起止锚点候选，采用前须经候选审核；不按段落顺序自动推断时间，未知端点可保留原设置。相对与未定时间另有无刻度示意图，连线表示已记录的先后，无连线不表示同时或先后。所有事件保留在表格中，显示顺序不代表已证明的完整故事顺序。

初始持有人和位置为未知。首次交接不会反推此前持有人；确定的错误交出者会阻止采用；同一状态受同时、重叠或先后未定的事件影响时保留未知。争议事件可保留证据，排除其状态变化。完整状态扩展和有效期规则见上节。

「按故事时刻查询」可输入任意相对分钟，选择包含／不包含同刻结束的事件，查看当时的物品持有者和人物所在地。区间内的动作尚未完成时保持未知；区间起点之前保留前态，区间终点之后才应用完成效果。相对／未定事件若可能跨过查询时刻，会按受影响对象标明未知及原因；明确的后续事件可覆盖较早不确定状态。查询结果附每项依据及定位原句，使用同一正式修订快照，重运行时随正式修订重算，不调用模型。时间轴上的虚线标记当前已提交的数值查询时刻。

## Harness 接口

现已通过 Python SDK 接入 **DeepSeek Harness**，固定 `deepseek-harness-sdk==0.1.5rc1` 和同版随包运行时。UI／CLI 调用 `Operations`，由独立适配器运行模型；结果只进入候选，正式采用继续由已有审核操作负责。

在「提取交接」操作：

1. 展开「模型服务设置」，选择供应商，填写账号可用的精确模型 ID，然后点击「保存服务设置」。默认保留用户指定的 `https://ark.cn-beijing.volces.com/api/plan/v3` 与 `Doubao-Seed-2.1-pro`。各供应商的地址、模型、参数和密钥环境变量名称分别保存，切换后可恢复；切换列表但未保存时不能启动提取。
2. 在密码框输入密钥，或设置页面显示的环境变量。读取顺序为本次密码框、该变量的进程环境、Windows 用户环境、Windows 系统环境。Windows 用户／系统设置在启动提取时直接读取，无需重启工作台；如果进程里已有旧值，它仍优先，需要更新或重启启动进程。页面只显示是否检测到密钥。不同供应商不自动借用其它供应商的变量；切换服务、地址或变量名称会清空本次密码框。密钥不写入项目设置、候选或导出包。
3. 选择章节，创建分块任务，查看发送范围，点击「启动模型提取」。任务串行执行，状态每两秒刷新；界面重运行不会再次发送。
4. 提取结束后点击「刷新页面以审核候选」，在「候选审核」核对原句、编辑并接受／拒绝。接受后才会修改正式资料。

当前适配范围是 **Chat Completions 兼容接口**，不把原生 Anthropic Messages、Gemini 或仅 Responses 的地址当成已接入。Harness 仍管理模型轮次，本机参数适配器按服务设置移除未启用的推理参数、转换输出上限字段，再转发原始流式响应。OpenAI 预设使用 `max_completion_tokens`，其他预设使用 `max_tokens`；均可在高级设置中调整。推理强度留空表示不发送该参数，避免 SDK 的默认 high 误传给不支持的模型。适配器只监听本机临时端口并使用独立临时令牌，不重试、不跟随重定向，不上传额外日志。

OpenCode Go 默认基础地址为 `https://opencode.ai/inference/go/openai/v1`（依据 2026-10-17 官方文档）；模型 ID 填控制台中支持 Chat Completions 的名称，不加 OpenCode 客户端的 `opencode-go/` 前缀。选择 Go 并保存后，在密码框输入 Go 密钥，或设置 `OPENCODE_GO_API_KEY`。官方会话头是 **`x-opencode-session`**：适配器自动使用实际 DSH 会话 ID `extract-<任务ID>-<分块序号>`，同一会话内所有转发请求保持相同，独立分块／任务使用不同标识；不需要用户填写。标识在 SDK 启动前绑定，结束或异常后释放，拒绝缺失会话或重叠调用，避免沿用上一分块的标识。客户端如实标为 `narrative-core/0.1.0`；不会伪装成 OpenCode、Codex 等客户端。Go 官方主要面向编程代理，小说提取的用途支持需向服务方确认；仅实现协议适配，不代表已完成 Go 真实账号联调。上述逻辑位于 Harness／网络适配器，界面继续通过 `Operations` 获取与保存供应商设置。

Go 接入验收：24 项供应商定向测试、483 项全量回归、Ruff 和使用项目解释器的 Pyright 通过。测试使用真实固定版 Harness SDK／运行时与本地模拟服务，不调用 Go 真实账号；结果在 `data/opencode-go-acceptance.json` 和对应 XML 中。

「提取交接」现显示任务输入／输出／总 Token、分块明细，以及「项目 Token 统计」中的项目累计和供应商／模型分组。每两秒随任务状态更新。统一通过 `Operations.token_usage(run_id=None)` 查询；传任务 ID 只统计该任务。统计直接读取已保存的分块用量，手工修正、重复导入、采用或拒绝候选不会重复累计，重开与备份恢复后保留。

新请求开启流式用量返回，网络适配器只读服务返回的 usage：一次请求的连续累计帧取最后一份，多次请求分别计入；同时保留旧版 SDK 驼峰字段与原生 API 字段的读取兼容。空响应、格式错误或失败结果也保存已取得的用量。未返回用量、被中断的流和旧记录缺失值保持未知；有已知小计但统计不完整时显示 `≥`，不会以零替代未知。缓存输入和推理输出作为输入／输出的子项展示，不再次加到总 Token。没有总数字段且输入、输出均明确时，以两者相加；不根据字符数估算，不推算费用。手工导入但未附服务用量的分块同样显示未知，项目统计不是服务商账单。

Token 统计验收：508 项全量回归、Ruff 和 Pyright 通过，覆盖流式累计与分片、缺失和零用量、空／错误响应、模型分组、手工修正不重复累计、备份恢复与界面显示；未新增云端模型调用。当前结果见 `data/token-acceptance.json` 和 `data/token-acceptance.xml`。

引文定位失败时，在「提取交接」选择任务与分块，展开「修正证据后重新导入」。分别修改断言／事件引文，查看上下文，并为重复原句或错误位置选定证据，再点击「保存修正并导入候选」。两类条目的编号和位置选择互不混用。格式或其它字段错误可在同一区域修改完整 JSON。此流程复用保存的响应，不调用模型；首次响应及服务元信息、每次修正前后内容和所选位置保留在分块记录中，随项目备份。已经导入的结果在候选审核中编辑，不能从修正界面覆盖。

每个分块使用独立 DSH 会话；应用发送固定分块、已有实体、任务创建时的已有事件快照（含证据）和结果格式，界面显示发送范围及快照数量。专用配置禁用默认 shell 工具、供应商会话日志上传、包清单注入和自动重试。DSH 会话状态保存在 `data/harness/<运行ID>/`，正式结果和候选保存在项目 SQLite；项目备份包括提取结果，不包括可重建的 SDK 运行目录。

任务、参数、提示词版本、输入哈希、原始输出、返回终态及可获得的用量保留在项目中。缺失用量保持未知。错误、截断、JSON 或证据校验失败均保留原因，不伪装成成功。失败／中断后不会自动重发，需要人工创建新任务；这也避免超时后的盲目重复计费。

「停止提取」会关闭本地 SDK 运行时并阻止后续分块和未导入结果进入候选，已经生成的候选仍保留供审核。不能据此判断供应商是否已经计费。项目使用 OS 文件锁保护活动任务；重启后将失去执行进程的任务标为中断，不恢复模型请求。

已使用**真实 SDK 与随包运行时 + 本地模拟模型服务**验证提取到候选审核，以及错误、截断、取消、超时和重复启动。火山方舟真实服务已完成短句提取并生成可定位候选；早期演示整章在 DSH 默认 high 推理强度下触及 120 秒上限，没有自动重试。方舟旧配置默认 low；新适配器在留空时移除该参数。各预设的离线协议验证不等于各供应商真实账号联调，也不构成模型质量成绩。

原有离线交接仍可使用：导出输入包中有固定源版本、父修订、提示词版本、结果 JSON Schema、已有实体／事件，以及含重叠的所有分块。新版任务将提示词和 Schema 一并保存，历史 v1 任务按原版本导出。下载包包含原文；只有点击启动提取才会发送模型请求。

结构化结果示例见 [examples/harness_result.json](examples/harness_result.json)。临时实体 `ref` 会转换为本地新 ID；引用已有实体时使用输入包中的稳定 ID。新实体的姓名重复只提示核验，不自动覆盖。

事件示例见 [examples/harness_events_result.json](examples/harness_events_result.json)，对应原文为 [examples/events_story.txt](examples/events_story.txt)。事件 `ref` 与实体 `ref` 属于不同命名空间；`after_event_ref` 可引用已有事件的稳定 ID，或同批事件（可前向引用）的临时标识。不同分块的候选不自动合并或串联，跨块先后需人工核验。人物声称、计划的动作仍作为主张核验，不能直接当作已发生事件。无明确时间锚点时保留 unknown／relative；唯一引文的 `quote_start` 可填 null，由程序精确定位。

返回的 `quote_start` 相对于分块起点，使用 Unicode 字符索引；省略时只有唯一匹配才接受。候选只定位当前分块中的证据。原始响应与失败原因持久保存，失败分块可重导；成功分块重复导入相同内容幂等，换结果须新建任务。

任务状态 `complete` 表示所有分块结果已解析，**不表示提取准确、没有遗漏或候选已采用**。重叠分块候选不按相似文本自动合并，审核时可删除重复操作、对齐实体 ID 或拒绝候选。接受一批后，其余旧修订候选须查看最新差异再更新基准。固定 705 字《背影》v11 真实请求生成了预检通过的候选，但独立审查仍发现语义错误，原样候选已拒绝；经有审计的 Operations 审修和独立复核后才接受，随后另用原文证据修订事件顺序。v10 真实请求因证据范围超合同失败。原样模型提取尚未稳定通过；审修后的闭环和原始模型质量分开评估。详见 [本轮记录](data/v11-live-20261017-f7c2/report.md)、[独立 QA](data/v11-live-20261017-f7c2/qa.json) 和 [开发计划](docs/PLAN.md)。

## 模块与操作层

UI、CLI 和后续 harness 统一通过 `operations.py` 的 `Operations` 调用功能：

```text
UI / CLI / harness
        ↓
Operations（查询、候选操作、提取交接、项目备份恢复）
        ↓
Service / extraction / checks / Store
```

界面负责输入、展示和交互状态，不直接访问数据库表，不自行组装变更或处理备份文件。操作层返回项目、候选审核、证据片段及下载数据，预期失败统一为 `OperationError`。内部模块不依赖 Streamlit；新增入口复用同一组显式 Python 操作，不新增调度框架。

最小无界面调用：

```python
from narrative.operations import Operations

app = Operations("data/book.sqlite3")
source_id = app.import_text("第一章", "林舟站在旧车站门口。")
candidate_id = app.propose_entity("林舟", "person", [])
review = app.review_candidate(candidate_id)
app.accept_candidate(candidate_id, review.version)
```

CLI 使用相同操作层：

```powershell
uv run narrative status
uv run narrative --db data/book.sqlite3 import chapter.txt --title 第一章
uv run narrative --db data/book.sqlite3 ui
uv run narrative check <候选ID>
uv run narrative accept <候选ID>
uv run narrative backup data/backups/book-01.sqlite3
uv run narrative restore data/backups/book-01.sqlite3 data/restored.sqlite3
uv run narrative export-input <原文ID> data/input.json
uv run narrative ingest-result <分块ID> examples/harness_result.json
uv run narrative extract <原文ID> --base-url https://ark.cn-beijing.volces.com/api/plan/v3 --model Doubao-Seed-2.1-pro
```
